# Phase D4 brief: host reference detector and resolution sweep

**Status:** finalized 2026-08-06. Work order for phase D4.
**Read first:** `/CLAUDE.md`, `v2/docs/DETECTION_CONTRACTS_D0.md`,
`v2/docs/PHASE_D3_BRIEF.md` (scorecard contract), `v2/configs/exp001_scene.yaml`.

## Goal

A host detector that turns U8 luma clips into frozen-contract Observation2D
streams, scored at three resolutions, plus the measured centroid number that
fires or clears the 0.75 px edge-only tripwire (D2 rule).

## Detector matrix (decided)

| Backend | Role |
| --- | --- |
| `fixed_bg` | Sanity baseline; proves plumbing against the D3 scorecard |
| `mog2` (OpenCV) | PRIMARY host baseline for all D4 scorecards (Samuel's decision). cv2 pinned in uv.lock, `cv2.setNumThreads(0)`, determinism proven by test |
| `ive_approx` (numpy) | Secondary backend whose parameters mirror the RK_MPI_IVE_GMM2 controls (model count, learning/variance knobs per the pinned Luckfox header). Exists so D8 board behavior can be predicted. Compared to mog2 by scorecard, never bit-parity |
| real IVE GMM2 | NOT this phase; D8, on the board |

Dependency rule (from finding F-D0-8): OpenCV becomes a required v2
dependency. If cv2 is missing, the detector REFUSES to run. No silent
pure-python fallback on the authoritative path, ever.

## Pipeline per backend

luma frame -> background model update (after warm-up schedule) -> foreground
mask -> threshold -> small morphology (config) -> connected components ->
component measurements -> short persistence (config) -> Observation2D.

Observation2D rules (frozen contracts): centroid reported in full-resolution
coordinates via the D0 scaling law; envelope declares proc resolution;
centroid covariance uses a floor from MEASURED repeatability (this phase
produces that number), never blob size alone; evidence_ref left null (the
host path has no patches; that is the edge node's job).

## The anti-tuning rule

Detector parameters are tuned ONLY on seed-variant datasets (same manifest,
different dataset seed) and synthetic fixtures. The golden gate clip and the
negative clip are scored ONCE per frozen configuration. Tuning on them is a
process violation.

## Measurements this phase must produce

1. Scorecards (quality/health/perf) for mog2 and ive_approx at 2304x1296,
   1536x864, 1152x648, on the clean gate clip and the negative clip.
2. Centroid repeatability and bias at the primary resolution (1536x864),
   expressed as full-resolution-equivalent sigma. Tripwire verdict against
   0.75 px, labeled Modeled (sensor noise is mid-bracket until the
   conversion-gain bench lands; the verdict is re-checked after).
3. Measured warm-up frames versus the manifest's 3 s.
4. False proposals per frame on the negative clip, per resolution.
5. `v2/docs/D4_DETECTOR_REPORT.md`: all of the above, every number labeled,
   generated by a seeded deterministic command.

## Inputs

The gate clip and the target-free negative clip, rendered on the 3070 Ti and
passed through the D3 sensor model. The dataset manifests must record render
device, driver, and Blender build (5.2.0); CPU and GPU renders are not
byte-comparable, so the golden clips are DEFINED as the 3070 Ti outputs.
Until the renders exist, develop and test against sensor-model fixtures;
the report requires the real clips.

```text
v2/tests/detector/
```
