## 3. The capacity decision, implemented

| Item | Before (D7) | After (D8) |
| --- | --- | --- |
| Datagram ceiling | 1200 B (Provisional) | 1472 B = 1500 MTU - 20 IPv4 - 8 UDP (Chosen) |
| `ObservationPacket.observations` max_count | 5 | 7 |
| Detector per-frame component cap | none | 7 |

Worst case the SCHEMA permits, measured by encoding rather than
estimated (`transport/sizing.py`): every string at its nanopb
`max_size`, every varint at its widest, a negative `capture_ts_ns`,
every optional present.

| Component | Bytes |
| --- | --- |
| Header | 4 |
| FrameEnvelope | 247 |
| Each Observation2D | 163 |
| Declared observation bound | 7 |
| Worst-case datagram | 1404 |
| Headroom | 68 |

The D8 opening entry predicted 251 + 7x163 = 1392 B with 80 B of
headroom. The encoder says 1404 B with 68 B, because the planning arithmetic omits the
repeated field's tag and length overhead, which widens as the packet
grows. The conclusion is unchanged — 7 fits, 8 does not — and the
difference is recorded rather than smoothed over: `sizing.py` derives
the bound by encoding for exactly this reason.

**Invariant, tested (E1): wire `max_count` >= detector cap.** The wire
bound is what the peer's nanopb ALLOCATES from, so a cap above it would
build capture events this host encodes happily and the board cannot
decode. The daemon refuses such a configuration at startup rather than
discovering it on a cluttered frame.

**Golden byte fixtures: unchanged.** `max_count` is an allocation
bound, not a wire value, so raising it moved no encoded byte. The D7
`wire_golden/*.hex` files are untouched and still gate W1.

## 4. Wire byte-identity (the absolute gate)

For identical observation inputs, the daemon's nanopb encoding must be
byte-identical to the host codec. Both encoders are handed the same
`observations.swob` bytes — a JSON fixture would have let a reader's
rounding masquerade as an encoder's disagreement.

| Fixture | Capture events | Observations | Max obs/event | Max datagram B | nanopb == host codec |
| --- | --- | --- | --- | --- | --- |
| sparse | 39 | 156 | 4 | 350 | **yes** (39 datagrams) |
| clutter | 39 | 273 | 7 | 540 | **yes** (39 datagrams) |
| gate | 283 | 283 | 1 | 161 | **yes** (283 datagrams) |

Plus an adversarial fixture no clip produces: an all-zero bbox origin
(a PRESENT but empty submessage), `local_blob_id` absent versus 0,
`evidence_ref` absent versus the empty string, a negative
`capture_ts_ns` (a full 10-byte varint), negative bbox origins through
the zigzag path, every string at its declared bound, and a full
7-observation event. Byte-identical on all of them, in both
directions, with unknown-field tolerance checked at the C boundary.

**Verdict: EXACT**, measured over 361 datagrams. No tolerance was
needed and none is permitted here.

| sparse | 60 | 39 | 156 | 156 | 0 | 0 | **yes** |

**The portable detector is byte-exact against the oracle on this
host.** That is stronger than the declared tolerance in section 6,
which remains the contract. It holds because `sw_detect_soft.c` is
a faithful transcription of the `ive_approx` backend — same

It says nothing about the board. The hardware GMM2 is a different

D8.2 measures it against the bounds declared there.

## 9. Findings

### D8-F1 — the cap ranks by a confidence the detector does not have

The D8 opening says the cap keeps "the top components by descending
confidence". The D4 detector has no confidence model: it is a
background model plus connected components, and every observation it
emits carries `confidence = 1.0`. A bare confidence sort is therefore a
total tie, and the survivors would be whatever order the components
arrived in.

The full ranking key is written down instead (`detector/cap.py`), with
the tie-breakers in priority order: `-confidence`, then `-area_px`,
then raster order. Area is the level that actually decides today; it is
the evidence the detector does have, a larger foreground region is a
better-conditioned centroid, and it matches the edge byte governor's
intent as closely as a model-free detector can. Raster order exists
only to make the choice TOTAL, so the C daemon does not have to
reproduce an accident of Python's sort.

Consequence if shipped: the cap's selection is deterministic and
area-driven, not confidence-driven, and it will stay that way until the
NPU appearance gate (phase 2 of the node design) gives `confidence`
something to mean. Anyone reading "top by confidence" in the decisions
log should read this finding first.

### D8-F2 — the health plane has one drop counter and three causes

The brief requires dropped components to be counted "in detector stats
and the health path, never silent". `HealthPacket` has exactly one
counter field, `drops`, and adding a second would be a wire change this
phase is not sanctioned to make — the D8 opening sanctions the capacity
touch and nothing else.

So `drops` is defined as the TOTAL of measurement items the node did
not send: frames the detector failed, components the cap removed, and
capture events that could not be encoded. The daemon keeps the three
separated in `--stats` and in its log; the Jetson sees the sum.

Consequence if shipped: a node that is dropping measurements says so
every second, and an operator cannot tell WHY from the wire alone —
they have to ask the node. Splitting the counter is a D9 lever and a
one-field wire decision; it is recorded here rather than taken.

### D8-F3 — the cap amplifies a sub-pixel divergence into a different
subset of measurements

Found by running the first host replay. With ten movers of nearly equal
area against a cap of seven, two detectors that agreed on every
centroid to a fraction of a pixel still sent 24% DIFFERENT
observations: a one-pixel area difference flips which components
survive the ranking, and the survivors are then disjoint.

That is why the detector tolerance is measured on the **sparse**
fixture, where the cap is inert, and why the clutter fixture is used
for the cap, the counters and the health path instead. Reporting them
together would have logged a selection effect as a detection error.

Consequence if shipped: on a crowded frame the host oracle can predict
that the board will send seven good measurements, and cannot predict
WHICH seven. Three nodes looking at the same crowded sky may each
forward a different subset, which is a fusion-association question for
D9, not a detector question. It is bounded — the cap keeps the largest
components, so the target is never the one dropped while decoys survive
unless the target is genuinely smaller than seven decoys — but it is
real and it is new.

### D8-F4 — OpenCV's 3x3 "ellipse" structuring element is a cross

`cv2.getStructuringElement(MORPH_ELLIPSE, (3, 3))` returns
`[[0,1,0],[1,1,1],[0,1,0]]`, not a filled 3x3 square. The daemon's
first transcription assumed the square, which eroded one extra ring off
every blob: a systematic ~1 px area deficit on every component, a
centroid shift of up to 1.1 full-res px, and — through D8-F3 — a
24% divergence in which components survived the cap.

The DECLARED tolerance is what caught it. The bound (0.5 px mean) was
committed before the first replay; the first measurement came in at
0.5414 px and breached it. After the fix the divergence is exactly
zero. A bound chosen after seeing the data would have been set at 0.6
and the bug would have shipped.

Consequence if shipped: none, because it did not ship. The general
lesson is the one the fixture policy is built on — a structuring
element is a detector parameter, not an implementation detail, and
"transcribe the oracle" means transcribing the library's choices too.

### D8-F5 — the daemon's socket counter is not its measurement counter

Measurement datagrams and the 1 Hz health packet leave through the same
socket, so the sender's `datagrams_sent` is a socket total and answered
the wrong question: a replay reported one more datagram than it had
capture events. Caught by the E5 cross-check between the packet log and
the counters, which exists precisely because the packet log is the
evidence the rest of E5 rests on.

Consequence if shipped: a D9 operator reconciling "datagrams sent"
against "observations received" would have found a permanent
off-by-N-health-packets discrepancy and gone looking for a lost
measurement. The stats now report measurement and socket totals
separately.

### D8-F6 — the detector reported one confidence and the cap ranked by
another, and nothing in the suite could tell

Late in the phase `runner.py` was found emitting
`confidence=min(1.0, area_px / 50.0)` — an area-derived confidence —
directly beneath a comment stating that the value is constant, while
`cap.py::component_confidence`, the C daemon's `sw_pipeline.c` and every
committed fixture still used 1.0.

The gap that let it hide is the interesting part. E2 and E5 both feed on
COMMITTED fixture bytes, so both stayed green: the daemon still agreed
with the fixtures, and the fixtures no longer agreed with the detector.
A fresh oracle run reproduced none of the committed packets, and the
host and the edge were putting different numbers in the same wire field
— the exact host/edge divergence this phase exists to eliminate.

Two tests now close it: one asserting that the confidence the runner
REPORTS is the value `component_confidence` returns (the cap's ranked
quantity and the reported quantity are one quantity), and one asserting
that a fresh oracle run still reproduces the committed packet bytes. The
runner now calls `component_confidence` rather than restating a literal,
so there is one place a real confidence model can ever land.

Consequence if shipped: the cap would have selected on a constant while
the Jetson received a variable, both looking reasonable in isolation,
and every committed fixture would have been quietly stale. If an
area-derived confidence IS wanted, it is a four-part change — `cap.py`,
the C daemon, a fixture regeneration with a recorded reason, and D8-F1 —
and a decision, not an edit.

Five lenses over the whole D8.0 diff — silent loss, encode/decode
asymmetry, C correctness and memory, tests that cannot fail, and
scope/labels/honesty — with every candidate finding handed to an
independent skeptic whose instruction was to REFUTE it and who could

hand-back.** The confirmed fourteen, because what a review caught is
more useful to the next phase than a claim that it found nothing:
